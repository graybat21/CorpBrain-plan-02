# 01_VPS_v5 주요 쟁점 검토 보고서

회비서님, `VPS_v5.md` 문서를 상세히 분석하여 요청하신 두 가지 핵심 쟁점에 대해 검토한 결과를 보고드립니다.

## 1. Kafka 기반 비동기 처리 필요성 검토
**결론: 초기 MVP 단계에서 Kafka 도입은 명백한 '오버 엔지니어링(Over-engineering)'이며, 제외하는 것이 합리적입니다.**

* **현 문서의 문제점**: 
  문서(IX. 3. 기술적 리스크)에는 '다중 채널(10개 이상) 연동 시 병목 현상'에 대비하여 Kafka 기반 비동기 처리 아키텍처를 적용한다고 명시되어 있습니다.
* **현실적 판단**: 
  * MVP의 핵심 타겟(C1)은 10인 미만 스타트업이며, 수익 모델의 Starter 플랜 기준 연동 채널은 2개입니다. 
  * Kafka는 대규모 트래픽 분산과 복잡한 실시간 데이터 파이프라인에 최적화된 도구입니다. 초기 구축, 운영, 유지보수(Zookeeper/KRaft, 클러스터 관리 등)에 막대한 인프라 리소스가 소모되므로 초기 스타트업의 MVP 스펙으로는 매우 부적절합니다.
  * **대안**: 초기의 비동기 큐잉 및 병목 방지는 **Redis (Pub/Sub 또는 Celery)** 나 클라우드 서비스인 **AWS SQS**와 같은 가볍고 관리가 용이한 기술만으로도 충분히 구현 가능합니다.
* **수정 권고**: 문서 내 리스크 대응 전략에서 'Kafka 기반'이라는 수식어를 삭제하고, '경량 메시지 큐(Redis/SQS 등) 기반 비동기 처리'로 하향 조정할 것을 권장합니다.

## 2. Local sLLM (HaaS 모델) vs 외부 API (SaaS 모델) 방향성 혼선 검토
**결론: 회비서님의 지적이 정확합니다. 현재 `VPS_v5.md`는 회비서님의 초기 구상인 '로컬 HaaS(정수기 모델) + 완전 망분리'에서 벗어나, '외부 LLM API를 사용하는 SaaS 모델'을 MVP의 기본 전제로 깔고 있습니다.**

* **문서 내 불일치 요인 분석**:
  * **현 문서의 구조**: 문서는 '빠른 시장 침투'를 위해 10인 미만 스타트업을 MVP 타겟으로 잡았습니다. 이를 위해 SaaS 형태로 서비스하며, 외부 API 비용 최적화(오픈소스 LLM 활용 등)를 언급하고 있습니다. 
  * **보안 대응 논리의 변경**: 데이터 유출 우려를 '망분리(로컬 설치)'로 해결하는 대신, 클라우드 전송 전에 개인정보와 영업비밀을 치환하는 **'기밀 마스킹 파이프라인(Privacy-Guard)'** 소프트웨어 기술로 우회하여 방어한다고 서술되어 있습니다.
  * **HaaS의 위치**: 회비서님께서 구상하셨던 "로컬에 설치하는 정수기 모델(HaaS) 및 Local sLLM"은 현재 문서 상에서 당장 구현할 MVP가 아니라, 추후 공공/금융 규제 시장(N1 타겟)을 뚫기 위한 **Phase 3 (Enterprise 전용) 장기 로드맵**으로 밀려나 있습니다.

* **의사결정을 위한 제언 (선택지)**:
  이 부분은 사업의 근본적인 **'고객 및 제품 정체성'**과 직결되므로 회비서님의 결단이 필요합니다.

  * **[선택 A] "초기 진입 속도"를 중시 (현재 VPS 논리 수용)**
    * 초기 물리 하드웨어 배포 비용이 없는 SaaS 형태로 시장(10인 미만 스타트업)을 빠르게 검증합니다.
    * 단, 완전한 망분리가 아니므로 보안 타협안인 '기밀 마스킹'의 완벽성을 시장에 설득해야 하는 과제가 생깁니다.
  * **[선택 B] "완전한 보안성"을 최우선으로 원안 고수 (수정 필요)**
    * MVP 타겟을 10인 미만 스타트업에서 '보안이 필수적인 중견/특수직군 기업'으로 변경해야 합니다.
    * 마스킹 논리를 축소하고 처음부터 워크스테이션(HaaS) 렌탈 모델과 로컬 sLLM 구축 비용/계획을 전면에 내세워 VPS 전체를 리팩터링해야 합니다.

## 💡 다온의 종합 의견
현재 `VPS_v5.md`는 전략적으로 **"현실적인 소프트웨어 개발(SaaS)과 타협"**을 한 흔적이 강합니다. 초기 자본과 개발 기간을 아끼기 위해 SaaS + 마스킹 구조를 택한 것으로 보입니다만, 이 경우 대표님이 강점으로 삼고자 했던 '절대 데이터가 외부로 나가지 않는 물리적 격리'라는 셀링 포인트가 초기에 희석됩니다.

두 가지 중 회비서님께서 우선시하는 핵심 가치(빠른 검증 vs 물리적 절대 보안)를 결정해 주시면, 그 방향에 맞춰 문서 구조와 전략을 다시 다듬겠습니다.

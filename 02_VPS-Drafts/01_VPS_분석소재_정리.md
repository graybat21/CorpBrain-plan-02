| **맥락 단절** | 동일 이슈임에도 지라의 결과(What)와 슬랙의 논의(Why)가 분리되어 **Context Collision** 발생 — 핵심 의사결정 맥락이 유실됨 |
| **감정** | 수작업 반복에 대한 **강한 피로감**, 정리를 건너뛰었을 때 핵심 정보가 누락될까 봐 느끼는 **불안과 허탈감** |
| **CJM 인지 단계 Pain** | 수많은 툴을 엮어줄 **단일 허브의 부재** — 개별 자동화는 있지만 '이기종 간 맥락(Context)' 병합 솔루션이 없음 |
| **CJM 고려 단계 Pain** | 또 하나의 새로운 툴(SaaS)을 배워야 한다는 **높은 심리적 장벽** |
| **CJM 결정 단계 Pain** | 슬랙/지라 API 연동(OAuth) 시 과도한 쓰기 권한 요구 → 보안 우려에 의한 **즉시 이탈 리스크** |
| **CJM 온보딩 Pain** | 첫 초안에서 **AI 할루시네이션(환각)** 발생 시 → 신뢰 상실 및 영구 이탈 |
| **CJM 충성도 Pain** | 업무 확장 시 **연동 채널 한계**에 부딪히면 병목 재발 |
| **핵심 니즈** | ① 단방향 API 백그라운드 수집(Zero-UI) ② 시간순·주제별 시맨틱 병합 초안 생성 ③ 가벼운 승인 절차(HITL 대시보드) ④ 원본 소스 딥링크 제공 |

## 2. JTBD 관점 인터뷰 결과 — 고객 상황에 따른 목표 서술 (Goal · Job)

### 2-1. C1 이수아 — Job Statement

> **Situation:** 프로젝트 마일스톤이 끝나고 여러 채널(슬랙, 지라)의 파편화된 히스토리를 노션에 취합해야 할 때
>
> **Job:** 내가 기존 툴 화면을 벗어나지 않고도 AI가 논의 맥락을 알아서 병합한 초안을 제공해 주어, **승인 클릭 한 번으로 문서화를 끝내고자** 함.
>
> **4 Forces:**
> - **Push:** 매번 여러 툴을 오가며 복붙해야 하는 단순 노동의 극심한 피로감
> - **Pull:** Zero-UI 백그라운드 수집과 '퇴근 전 승인 1회'라는 극강의 편의성
> - **Habit:** 울며 겨자 먹기로 노션에 수기로 타임라인을 정리하던 관성
> - **Anxiety:** AI가 할루시네이션(환각)을 일으켜 엉뚱한 내용을 요약할까 봐 불안

### 2-2. A1 강서연 — Job Statement

> **Situation:** 조직 내 부서 간 사일로를 해결하기 위해 새로운 지식 관리 솔루션의 도입 기안을 결재 올려야 할 때
>
> **Job:** 경영진의 기밀 반출 우려를 완벽히 차단하고, 절감된 인건비를 숫자로 보여주어 **한 번에 도입 승인을 받아내고자** 함.
>
> **4 Forces:**
> - **Push:** 과거 AI 툴 도입 시 경영진의 보안 우려로 반려된 경험
> - **Pull:** 강력한 기밀 마스킹 아키텍처와 대시보드 내 ROI 자동 산출 리포트
> - **Habit:** 비용과 보안 문제로 레거시 게시판을 억지로 유지하는 보수적 관성
> - **Anxiety:** 내부 정보 유출 시 모든 책임을 져야 한다는 두려움

### 2-3. E1 한유리 — Job Statement

> **Situation:** 슬랙, 잔디, 카톡 등 10개 이상의 채널에서 다수의 클라이언트 요청이 동시다발적으로 쏟아져 들어올 때
>
> **Job:** 수많은 채널의 파편화된 맥락이 꼬임 없이 **하나의 프로젝트 타임라인으로 정확히 시맨틱 융합**되는 것을 보고 싶음.
>
> **4 Forces:**
> - **Push:** 창 10개를 띄워놓고 수기로 관리하며 느끼는 패닉과 강박
> - **Pull:** 직관적인 수동 교정(HITL) UI를 통해 AI가 내 의도를 즉시 학습하는 쾌감
> - **Habit:** 클라이언트가 요구하는 각기 다른 메신저를 무조건 맞춰줘야 하는 업계 관성
> - **Anxiety:** 유사한 프로젝트명에서 AI가 내용을 섞어버리면 돌이킬 수 없는 사고 발생

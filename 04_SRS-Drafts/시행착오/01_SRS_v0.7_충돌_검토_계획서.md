# CorpBrain SRS v0.7 변경에 따른 충돌 검토 계획 및 초기 분석 결과

## 1. 개요
회비서 님의 요청에 따라 `04_SRS-draft_v0.7.md`에서 변경된 아키텍처(Next.js 풀스택, Vercel AI SDK, Enterprise LLM API 전환)가 기존 산출물들과 충돌하는지 검토하기 위한 계획 및 1차 분석 결과입니다. 
양과 범위가 넓으므로, 체계적으로 충돌을 해소하기 위한 단계적 접근을 제안합니다.

## 2. 검토 계획 (순차적 진행 단계)
- **Phase 1: 문서 간 명시적 충돌 탐색 (현재 1차 완료)**
  - `SRS v0.7` 내부의 자체 충돌 사항(다이어그램 등) 식별
  - 기반 문서인 `PRD v0.5`와의 아키텍처 제약사항(C-TEC) 불일치 검토
  - 기존 기술 검토 보고서(`01_C-TEC_분석_및_파서_추천보고서.md` 등)와의 방향성 충돌 점검
- **Phase 2: 충돌 항목 일괄 업데이트 (승인 후 진행 예정)**
  - 발견된 충돌 사항에 대해 회비서 님의 승인 후, 각 문서를 Next.js + Enterprise API 기반으로 일괄 업데이트 진행
- **Phase 3: 최종 정합성 및 키워드 검증**
  - 수정된 문서들 간의 Traceability(추적성) 점검 및 과거 키워드(`Gemma`, `RL` 등) 잔재 검색

## 3. 1차 충돌 분석 결과 (발견된 문제점)

### 🚨 충돌 1: `SRS-draft_v0.7.md` 내부 다이어그램 충돌
- **내용:** 본문 텍스트에서는 자체 구축 복잡도를 제거하고 Enterprise API(Azure/AWS)를 도입한다고 명시(C-TEC-004)했으나, **6.3.4 시맨틱 융합 상세 플로우 다이어그램(776 라인)**에서는 이전 버전의 내용인 `participant LLM as Self-Hosted Gemma LLM` 표기가 그대로 남아있습니다.

### 🚨 충돌 2: `PRD v0.5`와의 아키텍처 불일치 (Source 문서 충돌)
- **내용:** SRS v0.7은 PRD v0.5를 원천 문서(Source)로 삼고 있으나, PRD v0.5에는 Next.js App Router 도입(C-TEC-007)이나 Vercel AI SDK 적용 내용이 반영되어 있지 않습니다.
- PRD v0.5(227 라인)에는 여전히 `OpenAI / Gemma LLM API`가 혼용되어 기재되어 있습니다.
- 또한 초안 승인 데이터 기반의 **RL(강화학습) 피드백 루프** 등 MLOps 요소가 시스템 요구사항에 여전히 남아 있어, '바이브코딩 생산성 최적화'를 위해 MLOps를 완전히 배제하기로 한 최신 전략과 충돌합니다.

### 🚨 충돌 3: `01_C-TEC_분석_및_파서_추천보고서.md` 방향성 완전 불일치
- **내용:** 해당 보고서는 과거 "Self-Hosted Gemma sLLM 자체 구축"을 전제로 작성되었습니다. 이로 인한 생성 품질 저하를 막기 위한 대안으로 **"RL 피드백 루프를 통한 지속적 파인튜닝 파이프라인 구축"**을 강하게 권장하고 있습니다.
- 이는 1인 IT 개발자의 생산성 확보를 위해 고부하 MLOps 요소를 배제하고 Vercel AI SDK를 채택한 SRS v0.7의 핵심 기술 전략(C-TEC)과 정면으로 어긋납니다.

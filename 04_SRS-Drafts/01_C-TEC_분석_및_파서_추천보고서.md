# CorpBrain MVP: C-TEC 검토 및 파서(Parser) 도입 추천 보고서

## 1. 개요
본 보고서는 `SRS-draft_v0.5.md` 내 기술적 제약사항(C-TEC) 중 구체성이 부족한 **C-TEC-003(파서 기술 조달)**에 대한 구체적인 오픈소스 라이브러리를 추천하고, 전체 **C-TEC 제약사항들이 MVP의 핵심 사용자 경험(가치 전달)을 훼손하지 않는지 검토**한 결과를 담고 있습니다.

---

## 2. [C-TEC-003] 파서(Parser) 오픈소스 라이브러리 구체적 추천

현재 MVP에서 수집하는 데이터는 Slack Events API 및 Jira Webhooks를 통한 JSON 페이로드입니다. 이 비정형 텍스트(Slack의 mrkdwn, Jira의 ADF 등)를 정제하고 메타데이터(발화자, 타임스탬프, 딥링크)를 추출하기 위한 파서가 필요합니다. 본 프로젝트의 스택(Next.js/TypeScript 중심)을 고려하여 다음과 같은 조합을 추천합니다.

### 추천 1: 페이로드 검증 및 메타데이터 추출용 (필수)
*   **추천 라이브러리:** **Zod** (TypeScript Schema Validation)
*   **도입 사유:** 외부 Webhook에서 들어오는 JSON 데이터의 구조는 예기치 않게 변경되거나 누락될 수 있습니다. Zod를 사용하여 `author`, `timestamp`, `source_deeplink_url` 추출을 강제(Schema Validation)하면, 핵심 가치인 **Trust-Anchor(100% 딥링크 매핑)** 실패 리스크를 원천 차단할 수 있습니다.

### 추천 2: 이기종 마크업 언어 정규화용 (필수)
*   **추천 라이브러리:** **Unified (remark / rehype) 생태계**
*   **도입 사유:** Slack은 자체적인 마크다운(`mrkdwn`)을 사용하고, Jira는 ADF(Atlassian Document Format)를 사용합니다. 이를 정규식+NER 마스킹(Privacy-Guard) 모듈에 넘기기 전에 순수 텍스트(Plain Text)로 정규화하는 파싱 작업이 필수적입니다. AST(추상 구문 트리) 기반의 Unified 생태계를 사용하면 정교하고 안전한 텍스트 파싱이 가능합니다. (예: `slackify-markdown` 결합)

### 추천 3: 첨부파일 텍스트 추출 파서 (선택 / 고도화 시)
*   **추천 라이브러리:** **Unstructured** (Python/API) 또는 **LangChain Document Loaders** (TypeScript)
*   **도입 사유:** MVP 범위에서 텍스트 메시지뿐만 아니라 첨부된 문서(PDF, Word) 내용까지 시맨틱 융합에 포함해야 한다면, 문서 구조를 파악해 텍스트를 추출하는 전문 파서가 필요합니다. Unstructured는 현존하는 가장 강력한 오픈소스 문서 파서입니다.

> **💡 최종 추천 (Action Item):**
> MVP 단계의 일정 방어와 성능을 위해 무거운 전문 문서 파서보다는, **Zod(스키마 검증) + Unified/Remark(마크업 정규화)** 조합을 파이프라인의 Data Parser Module로 채택할 것을 권장합니다.

## 3. [C-TEC 검토] MVP 핵심 사용자 경험(가치 전달) 훼손 여부 분석

CorpBrain MVP의 핵심 가치 전달 요소는 **① Zero-UI 기반 TTC 10분 이내 단축 (C1 대상)**, **② Trust-Anchor 딥링크 100% 보장 (E1 대상)**, **③ Privacy-Guard 기밀 유지 (A1 대상)** 입니다. C-TEC 요소들이 이를 훼손하는지 점검했습니다.

### 긍정적 영향 (가치 강화)
*   **C-TEC-001 (경량 메시지 큐 비동기 분리):** Rate Limit 등으로 인한 외부 API 호출 실패나 데이터 유실을 방지합니다. 사용자의 텍스트가 누락되지 않아 **Zero-UI 신뢰도 향상**에 긍정적입니다.
*   **C-TEC-002 (PostgreSQL 통합 사용):** 원시 데이터와 생성 초안을 단일 DB 트랜잭션 내에서 관리하여 딥링크 매핑의 정합성을 높입니다.
*   **C-TEC-005 (Slack/Jira Read-only 권한):** 결재권자(A1)의 가장 큰 허들인 권한 탈취 및 데이터 변조 우려를 원천 차단하므로, **보안 가치 전달을 극대화**합니다.

### ⚠️ 핵심 위험 요소 및 보완책 (가치 훼손 가능성)
*   **C-TEC-004 & C-TEC-007 (Enterprise API 및 Next.js 단일 프레임워크 도입):**
    *   **도입 사유 (가치 강화):** 기존에 검토되었던 sLLM(Gemma 등) 자체 구축은 데이터 보안(A1) 측면에서는 유리하나, 1인 개발 체제에서 극심한 MLOps 유지보수 부하를 유발하고 융합(Semantic Fusion) 품질을 떨어뜨립니다. 이를 해결하기 위해 **데이터를 학습에 사용하지 않는 보안 인증(SOC2) 기반 Enterprise API (Azure/AWS)**를 도입하여 생성 품질과 보안을 동시에 달성합니다.
    *   **아키텍처 이점:** **Next.js (App Router) 기반 단일 풀스택 프레임워크와 Vercel AI SDK**를 활용함으로써, 복잡한 자체 AI 인프라 없이 '바이브코딩' 생산성을 극대화하고 개발 일정을 획기적으로 단축하여 핵심 가치인 'TTC 10분 이내 달성'을 수호합니다.

*   **C-TEC-006 (융합 엔진 중단 시 Webhook 수신 유지):**
    *   **리스크 분석:** LLM 서버 장애 시 수집(큐 적재)은 하되 생성은 대기하는 구조입니다. 이 경우 사용자는 문서를 원하는 시점에 초안을 받지 못해 대기 시간(TTC)이 길어집니다.
    *   **보완책 제안:** 대시보드 UI에 명확히 "AI 서버 지연으로 초안 생성이 대기 중입니다. 데이터 수집은 안전하게 보관되어 있습니다."라는 알림을 주어 사용자 경험(UX) 훼손을 최소화하고 데이터 유실에 대한 불안을 해소해야 합니다.

### 4. 종합 결론
대부분의 C-TEC 제약은 MVP의 보안(Privacy-Guard)과 안정성(Zero-UI 유실 방지)을 위해 훌륭하게 설계되어 핵심 가치 전달을 돕고 있습니다. 
특히, 최신 아키텍처 전략에 따라 **MLOps 복잡성을 배제하고 Enterprise API(Azure/AWS) 및 Next.js 풀스택** 체제를 채택함으로써, 보안(A1) 요건을 완벽히 충족하면서도 실무자(C1)가 기대하는 최고 수준의 초안 생성 품질을 제공할 수 있게 되었습니다. 1인 개발 체제 하에서도 빠르고 안정적인 MVP 론칭 및 성공률 극대화가 가능할 것으로 판단됩니다.

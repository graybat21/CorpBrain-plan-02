# CorpBrain 시스템 및 비용 효율성 통합 검토 계획서

## 1. 검토 목적
회비서 님의 요청에 따라, `SRS-draft_v0.7.md`를 **1) 개발 속도, 2) 외부 연동 기술 스택, 3) 운영 소요 비용**의 3가지 효율성 관점에서 검토하고, MVP 기획을 최적화하기 위한 구체적인 액션 아이템을 도출합니다.

## 2. 세부 검토 계획 및 1차 분석

### 2.1 개발 속도 (MVP 단계 과도한 시간 소요 방지)
- **점검 포인트:** 아키텍처 단순화를 통해 1인 개발 시간(Vibe Coding)을 지연시킬 요소 발굴
- **1차 식별 이슈:** `F4 Privacy-Guard` 항목에 **NER 모델(Named Entity Recognition)** 이중 적용이 명시되어 있음. 이는 파이썬 기반의 ML 모델 서빙 인프라 구축을 강제하여 Next.js 단일화 전략을 위반함.
- **해결 방향:** NER 모델 서빙을 폐기하고, **정규식 + LLM Zero-shot 프롬프팅**으로 PII 마스킹을 대체하여 개발 공수 극단적 단축.

### 2.2 외부 연동 목표와 기술 스택 (적절성 및 리스크)
- **점검 포인트:** 도입하려는 외부 오픈소스 및 기술 스택이 Next.js/Vercel 생태계와 얼마나 부합하는가?
- **1차 식별 이슈:** `C-TEC-001`에서 일반적인 **경량 메시지 큐(Redis 등)**를 언급하고 있으며, 파서 또한 막연한 오픈소스 활용이 언급됨.
- **해결 방향:** Next.js Edge 환경에서 완벽히 동작하는 **Serverless Redis (Upstash)** 및 **Supabase(PostgreSQL)**, 그리고 TypeScript 생태계 파서(Zod, Unified)로 스택을 구체화하여 통합/연동 리스크 해소.

### 2.3 운영 소요 비용 (클라우드 컴퓨팅 기반 비용 산정)
- **점검 포인트:** 월 단위 고정 비용(Fixed Cost)을 최소화하고 철저한 사용량 기반(Pay-as-you-go)인지 확인
- **해결 방향:** 
  - Vercel (Frontend & Serverless API)
  - Supabase (PostgreSQL DB)
  - Upstash (Serverless Redis)
  - Enterprise LLM (Azure OpenAI 등)
  위 4가지 스택을 기반으로 초기 사용자 100명 기준의 **월별 운영 비용 시뮬레이션 표**를 작성하고, MVP의 수익성 한계(인당 토큰비용 상한 $3) 준수 여부를 정량적으로 검토하는 보고서 작성.

# Phase 2: 시스템 제약 및 예외 케이스(Edge Case) 명세화 초안

물리적 제약이나 외부 종속성 오류로 인해 앱이 크래시(Crash)되거나 무한루프에 빠지는 것을 막기 위한 예외 처리 시나리오 명세입니다.

---

## 1. Windows 파일 시스템 제약 대응 (PRD F1, F4 영역 보완)
**[문제 상황]** Windows OS는 기본적으로 파일 경로 길이가 260자(MAX_PATH)를 초과하면 에러를 뱉으며, 관리자 권한이 필요한 시스템 폴더 등은 접근 권한이 없음(Permission Denied).
**[To-Be 방어 로직]**
- **경로 길이 초과 (Path Too Long):**
  - 스캔 중 260자를 초과하는 파일/폴더 발견 시, 앱을 멈추지 않고 해당 항목을 스캔 대상에서 제외(Skip) 처리함.
  - 스캔 완료 후, UI 하단에 "경로가 너무 길어 분석에서 제외된 파일 N개" 형태의 경고(Warning) 토스트/모달 제공.
- **접근 권한 거부 (Access Denied):**
  - 스캔 권한이 없는 폴더를 만날 경우 Exception을 catch하여 조용히 무시(Skip)하고 다음 탐색을 이어감. 
  - (별도 에러 팝업을 띄우지 않아 사용자의 스캔 흐름을 방해하지 않음)

## 2. 외부 종속성 (로컬 LLM) 장애 대응 (PRD F2 영역 보완)
**[문제 상황]** 로컬 LLM 구동을 위해 Option B(Ollama)를 선택했으나, 사용자 PC에 Ollama가 설치되어 있지 않거나 백그라운드 프로세스가 죽어있는 경우.
**[To-Be 방어 로직]**
- **Ollama 연결 체크 (Health Check):** 분석 시작 전 `http://127.0.0.1:11434/api/tags`로 상태 체크(Ping) 수행.
- **Fallback UI 시나리오 (Ping 실패 시):**
  1. "Ollama가 실행되어 있지 않거나 설치되지 않았습니다." 안내 팝업 모달 노출.
  2. 모달 내부에 Ollama 공식 홈페이지 다운로드 링크 버튼 삽입.
  3. "API Key를 활용한 클라우드 분석(Option A)으로 전환하시겠습니까?" 대안 버튼 제공.

## 3. 대용량 파일 스캔 및 UI Freezing 방지 (PRD F1, F3 영역 보완)
**[문제 상황]** C드라이브 전체나 10만 개 이상의 파일이 있는 최상위 폴더를 선택할 경우, 파일 목록을 파싱하는 동안 메인 스레드가 막혀 화면이 하얗게 멈추는(UI Freezing) 현상 발생.
**[To-Be 방어 로직]**
- **비동기 워커(Async Worker):** 파일 탐색(os.walk 등)은 반드시 백그라운드 스레드에서 수행하여 UI 응답성을 유지함.
- **제한 및 페이징 (Limits):** 
  - 1차 스캔 시 최대 파싱 파일 개수 제한(예: 10,000개)을 둠.
  - 제한 도달 시 스캔을 일시 중지하고 알림: "파일이 10,000개를 초과했습니다. 분석 범위를 좁히시거나, '계속 스캔'을 선택해주세요."
- **실시간 프로그래스 UI:** Progress 바 상단에 현재까지 스캔된 폴더/파일 개수를 0.5초 주기로 갱신(Throttling)하여 보여주어 앱이 죽지 않았음을 시각화함.

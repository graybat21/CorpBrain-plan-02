# Phase 1: Input-Process-Output 및 임계치 명확화 초안

기존 PRD v0.7에서 개발자가 자의적으로 추측할 수밖에 없었던 모호한 '의도'들을, 테스트 및 구현 가능한 수준의 '명세(Specification)'로 구체화한 Draft입니다.

---

## 1. PII 마스킹 범위 및 방식 구체화 (PRD 1.2, F2 영역 보완)
**[As-Is]** "PII(기밀) 데이터는 `***`로 마스킹되어 전송됨"
**[To-Be]**
- **마스킹 범위 및 우선순위:**
  1. **정규식(Regex) 기반 100% 차단:** 주민등록번호/외국인등록번호, 신용카드 번호, 전화번호, 이메일, IP 주소.
  2. **Custom Dictionary (사용자 지정 단어장):** 사용자가 앱 설정에서 등록한 사내 기밀 프로젝트명, 주요 고객사명 등.
  3. **경량 NER (Named Entity Recognition) 기반:** 로컬에서 구동되는 경량 NLP 모듈(예: Microsoft Presidio)을 통해 사람 이름(Person), 조직명(Organization) 식별 후 치환.
- **마스킹 출력 형식:** 단순 `***` 대신 `[MASKED_ID]`, `[MASKED_EMAIL]`, `[MASKED_ORG]` 형태로 치환하여, LLM이 문맥(Context)을 잃지 않도록 보완함.

## 2. 일관된 Naming Rule 템플릿 (PRD 1.2, F4 영역 보완)
**[As-Is]** "AI 추천 기반의 일관된 Naming Rule 자동 일괄 개편"
**[To-Be]**
- **기본(Default) 템플릿 포맷:** `[{Date}]_{ProjectName}_{DocumentType}_{Seq}.{ext}`
  - `{Date}`: 문서 생성일 또는 문서 내에서 추출된 주요 일자 (YYMMDD 형식)
  - `{ProjectName}`: LLM이 폴더 내 파일들의 맥락에서 유추한 공통 프로젝트명 (띄어쓰기 없이 CamelCase 또는 언더스코어)
  - `{DocumentType}`: 문서의 성격 (예: 회의록, 기획서, 레퍼런스, 계약서 등 10개 이내 분류 사전에서 선택)
  - `{Seq}`: 동일 타입 문서 간 정렬을 위한 2자리 순번 (01, 02...)
- **예시:** `[260714]_CorpBrainMVP_회의록_01.docx`
- **사용자 커스터마이징:** 환경설정에서 위 템플릿 변수의 순서를 바꾸거나 제외할 수 있는 UI 제공.

## 3. "불명확한 파일명"의 임계치 조건 (PRD F3 영역 보완)
**[As-Is]** "파일명이 불명확할 경우 첫 1~2문단만 가볍게 읽어와 보완"
**[To-Be]**
- **코드 레벨의 '불명확함' 조건 (하나라도 만족 시 True):**
  1. **길이 제한:** 확장자(`.docx` 등)를 제외한 파일명의 길이가 **5자 이하**인 경우. (예: `기획.pdf`, `1.docx`)
  2. **포맷 제한:** 파일명이 **숫자**로만 이루어졌거나 특수기호 위주인 경우. (예: `20240101.docx`)
  3. **의미 없는 키워드 포함:** `새 폴더`, `제목 없음`, `복사본`, `Copy of`, `Untitled` 등 정해진 불용어(Stop-word) 사전에 매칭되는 경우.
- **처리 프로세스 (I-P-O):** 위 임계치에 걸릴 경우 파일의 앞단 1,000 Bytes(약 200~300단어 분량) 텍스트를 파싱하여, 추출된 텍스트와 파일명을 함께 LLM 메타데이터 분석 프롬프트로 전송함.

## 4. 다단계 분석 파이프라인의 Output 스펙 (PRD F3 영역 보완)
**[As-Is]** "빠르게 유추하여 리포트 생성", "하나의 프로젝트 구조화된 Wiki 마크다운 초안 생성"
**[To-Be]**
- **옵션 1 (파일명 기반 고속 분석) Output:**
  - **저장 포맷:** `JSON` 파일 (내부 스키마: 각 노드별 파일 절대 경로, 1줄 요약문, 중요도 Score(1~5))
  - **사용자 UI:** TreeView 형태의 탐색기 UI에 요약 정보가 라벨(Label)로 덧붙여진 형태.
- **옵션 2 (내용 기반 심층 분석) Output:**
  - **저장 포맷:** `Markdown (.md)` 텍스트 파일
  - **데이터 흐름:** 문서 파싱 -> 로컬 Vector DB (ChromaDB) 저장 -> 쿼리 및 요약 -> 하나의 Markdown 파일로 병합 병합 생성.
  - **Trust-Anchor(팩트체크):** 마크다운 내부에 `[원문 열기](file:///C:/Users/.../원본파일.docx)` 형식의 파일 프로토콜(file://) 딥링크를 삽입.

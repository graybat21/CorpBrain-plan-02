# 📁 루트 폴더 선택 시나리오 및 대응 전략 (초안)

사용자가 어떤 폴더를 선택하느냐에 따라 발생하는 극단적인 케이스(Drive 전체 vs 다중 프로젝트 vs 단일 프로젝트)를 커버하기 위한 3가지 대응 시나리오입니다.

---

## 🛑 시나리오 1: C드라이브 전체 등 과도한 혼재 폴더 선택 (Noise 99% 상태)
**[상황]** 사용자가 귀찮아서 `C:\` 또는 `내 문서` 상위 폴더 전체를 선택함. (시스템 파일, 개인 문서, 여러 해 묵은 프로젝트가 모두 혼재)
**[대응 전략: 방어 및 사전 필터링]**
1. **루트 폴더 경고 (Early Warning):** 선택한 폴더가 드라이브의 루트(`C:\`, `D:\`)이거나 사용자 홈 디렉토리일 경우 팝업으로 개입합니다.
   - *"드라이브 전체 스캔은 불필요한 시스템 문서까지 포함되어 매우 오래 걸립니다. 세부 폴더를 선택하시는 것을 권장합니다. (그래도 진행 / 폴더 다시 선택)"*
2. **블랙리스트 자동 제외 (Smart Ignore):** 
   - OS 및 개발 관련 시스템 폴더(`Windows`, `Program Files`, `AppData`, `node_modules`, `.git` 등)는 스캔 엔진(os.walk) 단에서 하위 탐색을 강제 스킵(Pruning)하여 리소스를 아낍니다.
3. **한계치 도달 방어:** 1만 개 스캔 도달 시 강제 일시정지 후 범위를 좁히도록 유도합니다.

## 🗂️ 시나리오 2: 여러 프로젝트가 혼재된 상위 폴더 선택
**[상황]** `C:\Users\문서\내_프로젝트들` 폴더를 선택함. 하위에 'A프로젝트', 'B프로젝트', 'C고객사' 폴더가 각각 존재함.
**[대응 전략: 클러스터링 및 맥락 분리]**
1. **Depth 기반 프로젝트 분할 (Clustering):** 
   - 모든 문서를 한 바구니에 담으면 AI가 A프로젝트와 B프로젝트의 내용을 섞어버리는 치명적 환각(Hallucination)이 발생합니다.
   - 루트 폴더 바로 아래에 있는 1-Depth 서브 폴더들을 각각 독립된 '프로젝트 워크스페이스'로 간주하여 Tree UI 상에서 시각적으로 분리(디바이더 선 등)합니다.
2. **Context Isolation (맥락 독립):**
   - 심층 분석(옵션 2) 시, 1-Depth 폴더 단위로 LLM 프롬프트를 격리하여 개별 처리합니다.
   - 결과물(Wiki) 역시 "통합 위키 1개"가 아닌, 서브 폴더별로 목차(Index)나 탭(Tab)이 나뉜 여러 개의 마크다운 문서로 생성합니다.

## 🎯 시나리오 3: 단일 프로젝트 폴더 선택 (Happy Path)
**[상황]** `C:\Users\문서\CorpBrain_MVP_Project` 등 특정 프로젝트 하나만 딱 맞게 선택함.
**[대응 전략: 노이즈 제거 및 사용자 수고 최소화]**
1. **Rule-based 불용 폴더 자동 해제:** 
   - 단일 프로젝트 안에도 쓰레기 데이터가 있습니다. 폴더명에 `archive`, `backup`, `old`, `과거자료`, `휴지통` 등이 포함되어 있으면, Tree UI 렌더링 시 해당 항목의 체크박스(☑️)를 **기본값으로 체크 해제(☐) 상태로 제공**하여 사용자가 일일이 끄는 수고를 덜어줍니다.
2. **중요도(Score) 기반 하이라이트:**
   - 고속 분석(옵션 1) 실행 시, AI가 기획서/결과보고서 등 핵심 골격 문서에 높은 점수(Score)를 부여하고, 이를 UI 상단으로 끌어올리거나 별도 색상으로 하이라이트하여 사용자의 빠른 리뷰를 돕습니다.
